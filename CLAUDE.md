# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

BB84 quantum key distribution (simulated with Qiskit Aer) used to derive an AES-256-GCM key for peer-to-peer file transfer. The package lives in `src/qkd` (src layout, installed with `pip install -e`):

- `core/`: protocol steps (`bb84_protocol.py`), simulated channel and Eve's attack (`quantum_channel.py`), AES-GCM/HKDF and the session key schedule (`crypto_utils.py`), the finite-key bound (`finite_key.py`), and `config.py`. **core must not import from services, usecases, or runner** (enforced by `tests/test_setup.py`).
- `services/`: wire framing (`wire.py`), transcript hashing over the wire (`transcript.py`), chunked file streaming (`file_stream.py`), reporters and JSON events (`reporting.py`), and the backend pieces: `node.py` (NodeService, the transfer orchestration), `transfer_store.py` (state machine + repository), `events.py` (EventBus), `discovery.py` (mDNS), `peer_client.py`, `process_runner.py`, `history.py`, `resume.py` (receiver's `.part` + sidecar for resumable transfers), `interrupted_store.py` (interrupted transfers on disk), and `api/` (FastAPI factory, routes, Pydantic models, error handlers).
- `usecases/`: `send_file` (Alice), `receive_file` (Bob), `eavesdrop_demo` (Eve), `mitm_demo` (Mallory, the man-in-the-middle demo), `handshake` (the signed hello/finished helpers they share), and `resume` (the sealed resume negotiation). These are workflows combining core and services.
- `runner/`: thin argparse CLIs `alice`, `bob`, `eve`, `node` (console scripts `qkd-alice`, `qkd-bob`, `qkd-eve`, `qkd-node`).
- `app/frontend/`: React 19 + Vite 8 + Tailwind v4 UI.

Running two nodes on one machine works: give each its own `--port`, `QKD_NODE_NAME`, and working directory (history.json and received/ are cwd-relative). Point a second Vite dev server at it with `VITE_API_BASE_URL=http://127.0.0.1:8001`.

## Architecture notes

### Wire protocol (send_file / receive_file / eavesdrop_demo)
Single TCP connection. Every message is a 4-byte big-endian length prefix plus JSON or raw bytes, and goes through `qkd.services.wire` only. Protocol sockets must come from `wire.connect_with_retry` or `wire.accept`, which set `TCP_NODELAY`; with Nagle on, two messages in a row from one side (Alice's qber then salt) stall about 40 ms on the peer's delayed ACK. The message order is fixed and must change in lockstep in **usecases/send_file.py, receive_file.py, handshake.py, eavesdrop_demo.py, and mitm_demo.py** (Eve forwards the hellos, parses up to the QBER verdict, then blindly relays the rest both ways, which also carries 4c/4d and Bob's receipt; Mallory's relay strategy runs Bob's side against Alice; the invariants tests share one ordered step list, `WIRE_STEPS` in **tests/invariants/support.py**, that drives a generic tamper/relay proxy; `WIRE_STEPS_RESUME` and `RESUME_FINAL_STEPS` add 4c, 4d and 6 for resume runs). Steps 0 to 4 go through a `TranscriptChannel`; "tracked" messages are hashed into the transcript, untracked ones are not:

0. Alice → `{"hello"}`; Bob → `{"hello"}` (tracked). Protocol version `v` is 3. Fields per mode (binary values base64): none `{v, mode, params}`; sign adds `id_pk`, `nonce` (32 B); hybrid adds Alice's `kem_pk` and Bob's `kem_ct`. `params` is `ProtocolParams.security_policy()` (`final_key_bits`, `eps_sec`, `eps_cor`, `qber_threshold`, `enforce_finite_key`, `reconciliation`) and must equal the receiver's. Each side runs `auth.verifier.check(peer id_pk)` on arrival; Alice sends no qubits unless it passed. On a version, mode, or parameter mismatch Bob still replies with `{v, mode, params}`, and both raise `PeerAuthError` (no fallback)
1. Alice → `{"n", "index", "qubits"}` (untracked; `channel_model.encode_pulses`/`decode_pulses`): of the `n` pulses sent, only those that clicked at Bob, one QASM2 string each, or null for a click from background alone (no photon); `index` is null when all `n` clicked (ideal channel). Alice's side emulates fibre loss and Bob's detector efficiency and background (`sample_clicks`); Bob's side measures the photons, flips each with the misalignment probability, and gives background clicks a random bit. Eve sits after the loss and attacks only arriving photons
2. Bob → one basis per clicked pulse; Alice → matching indices (positions in the clicked list)
3. Alice → `{"sample_indices"}`; Bob → `{"sample_bits"}`; Alice → `{"qber"}`. Both abort if `qber >= QBER_THRESHOLD`, then both compute the finite-key secure length (`core/finite_key.py`, from kept bits, distinct sample size, and the announced QBER) and abort, without sending anything, if it is below `final_key_bits` (unless `enforce_finite_key` is off)
3c. Reconciliation `cascade` only (tracked; `usecases/reconcile.py`, algorithm in `core/cascade.py`): Alice → `{"cascade_seed"}`; then rounds of Bob → `{"cascade": [[pass, start, end], ...]}` and Alice → `{"parities": [...]}` until Bob sends an empty list. Bob corrects towards Alice; the parities Alice reveals are counted (`leaked_bits`) and charged in the finite-key bound, which therefore runs after reconciliation. A bit flipped twice means inconsistent parities and raises `CascadeError`
4. Alice → `{"salt"}`, a fresh Toeplitz seed of n + m - 1 bits (hex); qkd_key = Toeplitz hash of the kept sifted bits down to `final_key_bits`. Both sides then take T = transcript digest and the session key K
4b. Sign and hybrid only (untracked): Bob → `{"finished", "confirm"}`: `confirm` = HMAC-SHA256 under `key_schedule(K).confirm` over `qkd-confirm-v1|bob|` + T, `finished` = ML-DSA over `qkd-finished-v1|bob|` + T + tag. Alice checks the signature (`PeerAuthError`), then the tag (`KeyConfirmationError`, reported as `aborted_qber`), then sends hers with role `alice`; Bob checks both before reading any file data
4c/4d. **Resume only** (untracked): with `resume=ResumeOptions(...)`, auth sign/hybrid, and `"resume": 1` in *both* `finished` messages (unsigned flag; it can only switch resume off or stall it): Bob → `{"resume_request"}`, Alice → `{"resume_grant"}`. Both are AES-GCM under HKDF subkeys of the session key (`derive_resume_key`, never the file key), AAD = T (+ SHA-256 of the request for the grant). Bob says how many chunks he holds and a hash of them; Alice answers the offset, or 0 with a reason if her file changed. A failed tag is `PeerAuthError` before any file data. If a side has resume off the step is skipped and the wire is the plain one
5. Alice → metadata as `tag(16B) + ciphertext` under `key_schedule(K).metadata` (zero nonce, AAD `qkd-file-meta-v1`), then one `tag(16B) + ciphertext` message per chunk under `key_schedule(K).file` (nonce = 8-byte base || 4-byte counter; AAD = SHA-256 of the canonical metadata JSON). There is always at least one chunk (an empty file is one empty chunk), and Bob rejects metadata whose `num_chunks` does not match `total_size`/`chunk_size` (`MetadataError`) With resume the metadata also has `sha256` (whole file) and `resume_offset`, and chunks start at the offset (chunk `i` keeps nonce base || i; every session draws a fresh base nonce)
6. **Resume only**: Bob → `{"resume_done"}`, a sealed receipt sent after size and whole-file SHA-256 verified and the file was renamed into place; Alice reports success only after reading it

Without `resume` (the default, and what every pre-existing test uses) none of 4c, 4d, 6 or the metadata fields exist and the wire is the plain one above.

The session key K is `derive_session_key(qkd_key, kem_ss, T, mode)`; in none mode (`auth=None`) that is `derive_aes_key(qkd_key)`. `crypto_utils.key_schedule(K)` expands it with HKDF-Expand into independent `file`, `metadata`, and `confirm` subkeys. Peers running an older protocol version cannot talk to current ones, even in none mode.

`services/wire.py`, `file_stream.py`, and `reporting.py` must not import qiskit (tested). Bob writes `received_<basename>` into `OUTPUT_DIR` and deletes the partial file on any tag failure. With resume he instead keeps `OUTPUT_DIR/.resume/<transfer_id>.part` (only AES-GCM-verified bytes) and `<id>.json` (atomic sidecar: file identity, chunks held, last base nonce, the sender's identity fingerprint), keyed by transfer id because the file name arrives after the negotiation; on a lost connection or bad tag he cuts the `.part` to the last verified chunk and raises `TransferInterrupted`; the final file appears by atomic rename after the hash check. A different authenticated peer identity than the sidecar's is refused before the `.part` is touched.

### Scope of the protocol
The channel defaults to `ideal` (no loss, no errors). `core/channel_model.py` models a lossy, noisy fibre and threshold detector for a single-photon source (Ma, Qi, Zhao, Lo 2005; presets `GYS`, `KTH`), selected with `QKD_CHANNEL_PRESET` and `QKD_CHANNEL_LENGTH_KM`. Reconciliation is `QKD_RECONCILIATION=none` by default (any error in the kept bits ends at key confirmation or the file tag) or `cascade` (original Cascade, validated against Martinez-Mateo et al. 2015: efficiency about 1.15 to 1.2). There is no decoy-state code yet (see the gitignored `docs/ignore-PLAN.md`). Eve parses up to the QBER message and then relays raw bytes both ways (`wire.relay_until_closed`), since the message count after it varies. If you add channel noise you must also add an interactive reconciliation step over the wire (and charge its leakage in `finite_key.py`), or key confirmation will fail. The default N = 8192 is the smallest power of two for which the finite-key bound gives 256 secure bits with the default eps values; at the old 128 it gives 0. Tests that study authentication or tampering rather than key length run small N with `enforce_finite_key=False`. `measure_qubits` submits all one-qubit circuits as one Aer job without transpiling (they use only native gates); do not go back to one job per qubit (about 250x slower). The QRNG is the Aer simulator (`_quantum_random_bits`), so importing `bb84_protocol` or `quantum_channel` pulls in qiskit.

### Reporters and events
Workflows never print. They call a `Reporter` (`section/info/success/warning/error` for humans; `stage/metrics/progress/listening/result` for structure). `ConsoleReporter` prints the human lines; `JsonEventReporter` (`--events json`) writes one JSON object per line: `{"type", "transfer_id", "stage", "payload", "ts"}`. The node and `scripts/benchmark.py` consume these, so **renaming a stage, metric key, or event type is an API change**: update `node.py` (`STAGE_STATUS`, `METRIC_FIELDS`), `api/models.py` (`TransferEvent.type`), and `app/frontend/src/api/types.js`. Log text is display-only; nothing parses it. Resume adds the result outcome `interrupted` and the metrics `resumed_from_bytes`, `bytes_total`, `resume_restart_reason` (mapped in `node.py` `METRIC_FIELDS`, its copy in `events.py`, `api/models.py` `Transfer`/`HistoryEntry`, and `types.js`); it adds no stage (negotiation runs inside `key_confirmation`). The handshake adds stages `authentication` (before step 0) and `key_confirmation` (before 4b, signed modes only) and the metrics `auth_mode`, `peer_fingerprint`, `peer_trust`, `handshake_ms`, `auth_overhead_bytes`; the key exchange adds `secure_key_bits` (finite-key bound). The node, API models, and frontend do not map these yet. Abort messages come from `KeyExchangeResult.abort_reason`.

### Backend node
`create_app(service)` builds the FastAPI app around a `NodeService`; `default_service()` wires the real pieces (Zeroconf discovery, httpx peer client, subprocess launcher). Tests inject `StaticPeerDirectory`, fakes from `tests/services/fakes.py`, and drive it with `TestClient`.

- REST resources under `/api/v1`: `node`, `peers`, `transfers` (+ `/incoming` for node-to-node offers, `/{id}/events` SSE), `history`. Errors are always `{"error": {"code", "message"}}`; domain exceptions map to status codes in `api/errors.py`.
- Both nodes store a transfer with the **same id**. Sender: POST `/transfers` → POSTs `/transfers/incoming` to the peer. Receiver: PATCH accepted → launches bob with `--port 0`, waits for its `listening` event, then PATCHes the sender with `receiver_port` → sender launches alice.
- State machine in `transfer_store.py`. API-driven moves must be valid single transitions (else 409); event-driven moves use `path_to` and may step through intermediate statuses. Use `NodeService._fail` (not `_move(..., failed)`) for failures after async work, because the runner may already have finished the transfer.
- Runners are spawned as `sys.executable -m qkd.runner.<role> --events json`, inheriting the node's environment (so `QKD_*` overrides apply to them).
- Transfers live in memory; finished ones are appended to `HISTORY_FILE` (gitignored). Uploads go to a temp dir and are deleted when the transfer finishes.
- Peers are contacted on the port they advertise over mDNS (TXT record carries the node id).
- **Resumable transfers** (`QKD_RESUME=1`; the node then passes `--resume` to its runners). Status `interrupted` is non-terminal: from `transferring` when a runner reports outcome `interrupted`, or dies in a signed mode with verified data. Its edges live in `transfer_store.RESUME_TRANSITIONS`, not `TRANSITIONS`, because `test_transition_table` pins the latter; use `can_move`/`path_to`, not `can_transition`, for them. Exits: `pending` (sender `POST /transfers/{id}/resume`, which re-offers the same id with `resume_transfer_id`; the receiver's interrupted transfer goes back to `pending` and is accepted like any offer), `cancelled`, `failed`. `Transfer.attempt` counts tries. Interrupted transfers are persisted in `QKD_STATE_FILE` (`interrupted_store.py`) and restored at start; the sender's upload is moved next to it while interrupted; finishing, cancelling or declining deletes the receiver's `.resume` state. An interruption also writes a history entry. Node ids are random per start, so resume offers and restarted peers are matched by PQC identity fingerprint (ids only when a fingerprint is missing). The resume route has `include_in_schema=False` because `test_openapi_schema_and_docs` pins the exact documented paths.

### Frontend
`src/api/client.js` is the only module that calls the backend (JSDoc-typed against `src/api/types.js`); components get data through `src/hooks/` (polling + `useTransferEvents` for SSE). Base URL from `VITE_API_BASE_URL` (default `http://127.0.0.1:8000`). Components are in `src/components/`; `ProtocolView` renders the stage sequence, key funnel, QBER scale, and chunk progress from the transfer resource. Theme tokens (palette, type scale) are in `src/index.css` (`@theme`); fonts are bundled with `@fontsource`.

## Configuration
Every tunable is in `src/qkd/core/config.py` and can be overridden with `QKD_<NAME>` (read once at import; tests check this in subprocesses): `NUM_QUBITS`, `QBER_SAMPLE_FRACTION`, `QBER_THRESHOLD`, `FINAL_KEY_BITS`, `EPS_SEC`, `EPS_COR`, `ENFORCE_FINITE_KEY`, `RECONCILIATION`, `CHANNEL_PRESET`, `CHANNEL_LENGTH_KM`, `FIBER_LOSS_DB_PER_KM`, `DETECTOR_EFFICIENCY`, `DARK_COUNT_PROB`, `MISALIGNMENT`, `CHUNK_SIZE`, `ALICE_HOST`, `BOB_PORT`, `EVE_PORT`, `BUFFER_SIZE`, `OUTPUT_DIR`, `HISTORY_FILE`, `NODE_PORT` (falls back to `PORT`), `NODE_NAME`, `NODE_HOST`, `AUTH_MODE`, `IDENTITY_DIR`, `KNOWN_PEERS_FILE`, `TOFU`, `RESUME`, `RESUME_SYNC_CHUNKS`, `STATE_FILE`, `MEASUREMENT`, `DECOY_GATE`. `ProtocolParams` bundles the per-run protocol values and is what the use cases take; its `channel` is physics, not policy, so it is not in the hello's `params`. `MEASUREMENT` (`aer` default, or `analytic`) and `DECOY_GATE` (`asymptotic` default, or `composable`) are likewise run knobs, not policy: both peers must set them the same, and they are not in the hello.

`MEASUREMENT=analytic` computes Bob's (and the PNS Eve's) measurement outcomes directly in NumPy with no Qiskit — exact for BB84 states with no per-qubit quantum attack (honest and PNS runs) — and carries qubits over the wire as integer codes `bit | basis<<1` instead of QASM strings, so the 1e6-1e8-pulse composable finite-key runs are tractable (Aer is not). The QRNG also goes to NumPy in that mode (`generate_random_bits(n, rng)`), and `sample_clicks_decoy` chunks its draw so a 1e8-pulse honest run stays under ~0.5 GB. `DECOY_GATE=composable` swaps the `decoy_asymptotic_verdict` for the Lim et al. (2014) composable finite-key bound (`core/decoy_finitekey.py`, `usecases/common.decoy_finite_key_verdict`), which charges the statistical fluctuations of the measured per-intensity gains/QBERs; `scripts/decoy_cluster.py` sizes runs against it with `required_N`.

## Experiments
`scripts/benchmark.py` runs a grid from `experiments/configs/e*.yaml` (E1 detection, E2 where runs stop, E3 secure length, E4 overhead, E6 latency; E5 wire bytes is drawn from E4) with real runner processes. The grid parameter `rtt_ms` puts `scripts/latency_proxy.py` between Alice and Bob (rtt/2 each way, no root, per connection) instead of `tc netem`. E7 is separate: `scripts/fuzz_tamper.py experiments/configs/e7_fuzz.yaml` changes one wire message per trial (semantic or bitflip; `applied` records a fallback) in in-process Alice/Bob runs and labels what caught it; `delivered_corrupt` must stay 0. Timing comes from the runners' event timestamps, not process wall time; `sim_ms` (Alice and Bob) separates simulator cost, and `protocol_minus_sim_s` is the protocol's own time. Each run is labelled by `stopped_at` (`classify`). All runs of an experiment execute in one seeded shuffled order (`run_plan`; seed from `--seed`, the config, or random, recorded as `run_order_seed`), so drift over a long session does not line up with a grid parameter; keep it that way. Each invocation writes its own never-overwritten run id folder `experiments/results/<experiment>/<YYYYMMDDTHHMMZ>_<commit7>[-dirty][-scratch]/` with `runs.csv` (appended per run), `summary.csv` (median/IQR, outcome rates with Wilson 95% intervals), `meta.json` (status, commit, versions, CPU, seed), and `log.txt`; `--resume <run dir>` finishes an interrupted one (refused if the commit changed). Only paper-grade runs (complete, clean tree, the config's repeats) move `<experiment>/latest`. Launch long runs with `setsid nohup` so they outlive the terminal. **Never edit tracked source while a run is going**: the runners import the working tree, so edits change the code mid-experiment; the harness re-checks the tree at the end and marks such runs `tree_changed_during_run` (not paper grade). Findings are kept by hand in `experiments/ignore-INSIGHTS.md` (gitignored, one entry per run id; conventions at its top). `scripts/plot_figures.py` reads only `latest/summary.csv`, per `experiments/figures.yaml`, and records each figure's run id in `experiments/figures/sources.json`; its colors are a validated categorical order and an ordinal blue ramp, keep them.
